## Design Context

### Users
Developers running complete coding tasks against local Git repositories. They need to submit a task, understand the agent's actions, inspect Jev model routing and judgments, review code changes, and verify actual test outcomes.

### Brand Personality
Precise, calm, professional. The interface should make agent behavior understandable and provide confidence through inspectable evidence.

### Aesthetic Direction
User explicitly requests English UI, developer audience, both light and dark themes, and a simple professional style. Use a restrained warm-paper workbench in light mode and charcoal/olive neutrals in dark mode. Forest green is the action accent. A compact sidebar, clear typographic hierarchy, chronological execution timeline, and an integrated diff/test inspector should feel like a focused development tool. Avoid decorative dashboards and excessive cards.

### Design Principles
1. Show real execution evidence; label scripted demo and model fallbacks clearly.
2. Keep task execution, model routing, changes, and verification one coherent workflow.
3. Distinguish model judgments from deterministic validation.
4. Use accessible contrast, visible keyboard focus, reduced-motion support, and responsive layouts.
5. Persist theme and keep advanced provider detail progressively disclosed.
